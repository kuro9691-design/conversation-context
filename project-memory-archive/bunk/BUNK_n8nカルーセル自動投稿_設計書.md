# BUNK — n8n カルーセル自動投稿ワークフロー設計書

作成日: 2026-08-10
用途: n8nが動いているPC上でClaude Codeを使って実装する際の設計仕様。認証情報(APIキー・アクセストークン等)はこのドキュメントには一切含めない。

## 前提

- Vol.1は手動投稿(このワークフローの対象外)
- Vol.2以降、準備が整った巻から自動投稿の対象にする
- 認証情報の扱いはBUNK制作スキルの方針に従う: APIキー・App Secret・アクセストークン等はn8nが動いているPC上でローカルに保持し、Coworkのチャットには一切貼らない

## 決定事項

| 項目 | 内容 |
|---|---|
| トリガー | 毎週金曜 6:00(JST)の自動実行 |
| 巻数判定 | 投稿カレンダーの「投稿日」列で当日日付と一致する行を検索 |
| 安全策 | 該当行の「準備完了」フラグ(人が手動チェック)がTRUEでなければ投稿せず通知のみで終了 |
| alt_text | v1から対応。「1行=1画像」タブに事前に格納しておく(n8nは読むだけ、生成しない) |
| 画像の公開URL化 | ワークフロー内で自動化(共有設定変更→URL変換までn8n内で完結) |

## 前提作業(n8n構築前にスプレッドシート側で必要)

### 1. 「1行=1画像」タブの新設

スキルの「今後の拡張予定」に記載済みの設計をそのまま採用。1行=1画像、144回×10枚=1440行。

列構成:
- 巻数
- 位置(00〜09、00=表紙)
- 役割スラッグ(cover, street, exterior, origin-object, interior, symbolic-object, workspace, person, climax, dawn-empty)
- プロンプト(本文用)
- alt_text(英語。プロンプト生成時にClaude側で場面描写から機械的に組み立てて先に埋める)
- 画像URL(n8n実行時に埋まる想定。事前入力不要)
- ファイル名(`vol{N}_00_cover.png` / `vol{N}_{位置:02d}.png`)

alt_textの組み立てルール(案): 該当カットのプロンプトのうち、共通スタイルブロックと人物指定を除いた「被写体, 時代・場所」部分をそのまま使う。例: `An 18th-century Paris restaurant exterior at night`

Vol.1分はすでに作成済み(スプレッドシートID `1ORcWdqVgFZ6crdF15bXNjwNXYwTxzsAs0If952DLr-Q` の「1行=1画像」タブ、またはコピー用の補助ファイル「BUNK_1行1画像タブ_Vol1(コピー用)」)。

### 2. 投稿カレンダーに「準備完了」列を追加

- 人が手動でTRUE/FALSEを立てる列(数式にしない。安全策として人の最終確認を必須にする)
- 条件: 画像整理完了・キャプション確定・「1行=1画像」タブへの当該巻10行の記入、すべて終わった時点でユーザーがTRUEにする
- Q列に追加済みのはず(未確認なら確認する)

## n8nワークフロー ノード構成

1. **Schedule Trigger**
   Cron: `0 6 * * 5`(タイムゾーンJST設定)

2. **Google Sheets: 投稿カレンダー行取得**
   投稿カレンダーから「投稿日」=今日の日付の行を検索。0件ならワークフロー終了(通知不要、想定内)

3. **IF: 準備完了フラグ判定**
   該当行の「準備完了」列がTRUEか判定
   - false → 通知ノードへ分岐(「Vol.N の投稿準備が未完了のため今週は自動投稿をスキップしました」)→ 終了
   - true → 続行

4. **Google Sheets: 「1行=1画像」タブ取得**
   該当巻数の10行(位置00〜09)を取得し、位置順にソート

5. **Google Drive(ループ10回): 共有設定変更**
   各ファイルの共有設定を「リンクを知っている全員が閲覧者」に変更

6. **Function: 公開URL組み立て**
   各ファイルIDから `https://drive.google.com/uc?export=view&id={fileId}` を生成

7. **HTTP Request(IG Graph API、ループ10回): カルーセルアイテムコンテナ作成**
   `POST /{ig-user-id}/media`
   パラメータ: `image_url`, `is_carousel_item=true`, `alt_text`
   レスポンスの `id`(コンテナID)を位置順の配列に保持

8. **Wait + HTTP Request: コンテナ生成完了待ち**
   各コンテナIDについて `GET /{container-id}?fields=status_code` をポーリング
   `FINISHED` になるまで待機(タイムアウト・エラー処理を設定)

9. **HTTP Request: カルーセル本体コンテナ作成**
   `POST /{ig-user-id}/media`
   パラメータ: `media_type=CAROUSEL`, `children=[10個のコンテナIDを位置順に]`, `caption=投稿カレンダーJ列の値`

10. **Wait + HTTP Request: 本体コンテナ生成完了待ち**
    同様に `status_code` をポーリング

11. **HTTP Request: 公開**
    `POST /{ig-user-id}/media_publish`
    パラメータ: `creation_id=カルーセル本体コンテナID`

12. **Google Sheets: 投稿カレンダーに書き戻し**
    投稿日時・パーマリンク(取得できれば)を該当行に記録

13. **通知ノード**
    成功/失敗どちらの結果もSlackやLINEなどに通知

## エラー処理の考え方

- 手順8・10のポーリングでコンテナが `ERROR` になった場合は即座に処理を中断し、通知ノードでエラー内容を通知する
- IG Graph APIのレート制限に達した場合の再試行間隔も合わせて設計する(実装時に確認)
